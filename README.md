# 飞书网关助手

通过飞书机器人远程控制 OpenClaw 网关重启。

## 功能

- 私聊机器人发送「重启网关」即可重启
- 首次发消息的用户自动成为授权管理员
- 执行结果实时反馈到飞书
- 90 秒重启冷却，防止网络抖动 / 消息重投导致连续重启
- 消息去重持久化到磁盘，进程重启后仍能识别已处理消息
- 健康检查脚本，失联后自动拉起机器人

## 安装

```bash
npm install
```

## 配置

复制 `.env.example` 为 `.env` 并填写飞书应用凭证：

```env
APP_ID=你的飞书应用ID
APP_SECRET=你的飞书应用密钥
AUTHORIZED_USER_ID=授权用户的 Open ID（首次运行后自动填写）
```

## 运行

```bash
npm start
```

或使用启动脚本（输出追加到 `bot.log`）：

```cmd
start_bot.cmd
```

## 使用方法

1. 启动机器人服务
2. 在飞书中私聊机器人，发送任意消息（首次会自动授权你为管理员）
3. 发送「重启网关」重启 OpenClaw 网关
4. 发送「帮助」查看可用命令

## 防重复重启

机器人内置多层防护，避免一条指令触发多次重启：

| 机制 | 说明 |
|------|------|
| 消息去重 | 同一 `message_id` 5 分钟内只处理一次，去重记录落盘 |
| 旧消息过滤 | 进程启动前发出的消息自动跳过，防止重连回放 |
| 重启冷却 | 两次重启至少间隔 90 秒 |
| 并发锁 | 重启进行中时忽略新的重启请求 |

## 健康检查

`healthcheck.ps1` 可配合 Windows 计划任务定期执行：

- 检测 `heartbeat.txt` 是否超过 5 分钟未更新
- 检测连接状态是否为 `failed` / `idle` / `unknown`
- 异常时自动杀掉机器人进程并重新拉起

## 目录结构

```

├── index.js              # 机器人主程序
├── healthcheck.ps1       # 健康检查脚本
├── start_bot.cmd         # 启动脚本
├── service.js            # node-windows 服务安装
├── service-uninstall.js  # 卸载服务
├── setup_autostart.ps1   # 开机自启配置
├── setup_tasks_admin.*   # 计划任务安装（需管理员）
└── .env.example          # 配置模板
```

## 注意事项

- 需要保持服务运行才能接收消息
- 建议设置为开机自启动或后台服务
- `.env` 包含应用密钥，已被 `.gitignore` 排除，请勿提交到仓库
